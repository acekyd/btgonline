
# Bravo Trashe Gaming (BTG) Platform
## Product Requirements Document + Architecture Specification — v2

---

# 1. Product Overview

The **BTG Platform** is the central website for the Bravo Trashe Gaming community.

The platform will:

- Showcase BTG creators
- Present tournaments across multiple games
- Archive tournament seasons
- Track historical football statistics across seasons
- Display all-time records and a hall of fame
- Provide admin tools for managing the ecosystem

The system must remain:

- simple
- secure
- maintainable
- data-driven

---

# 2. Goals

## Primary Goals

Provide a professional hub that allows visitors to:

- Discover BTG creators
- Browse tournaments
- Explore historical seasons
- View competition results
- See football statistics across seasons
- See all-time records and hall of fame

Provide admins the ability to:

- Manage creators
- Manage tournaments
- Manage seasons
- Import stats via CSV
- Merge players and teams across seasons

---

# 3. Non-Goals (V1)

Not included in version 1:

- Live match tracking
- Real-time event ingestion
- Player self-managed accounts
- Community user accounts
- Payment systems
- Automated identity detection

---

# 4. Core Product Principles

## Simplicity First
The platform must remain easy to maintain.

## Data Driven
Records such as top scorers and historical rankings must be computed from stored data.

## Admin Controlled
All content is curated by trusted admins.

## Security First
All admin operations must be authenticated and validated.

## Expandable
Architecture must allow adding additional games and tournaments later.

---

# 5. Technology Stack

Frontend
- Nuxt 3
- Vue 3
- TailwindCSS

Backend
- Nuxt Server Routes (Nitro)
- Node runtime

Database
- SQLite (via `better-sqlite3`)

ORM
- Drizzle ORM

Session Management
- `h3` built-in `useSession()` utility (Nitro native, no extra library needed)
- Session data encrypted with `SESSION_SECRET`

Password Hashing
- `bcryptjs` (pure JS, no native dependency issues on Render)

CSRF Protection
- `sameSite=strict` on session cookie is the primary protection
- All admin mutation endpoints additionally require the session to be present (effectively enforcing same-origin)
- No separate CSRF token needed given the strict sameSite policy and admin-only scope

CSV Parsing
- `papaparse` (browser + server compatible)

Rate Limiting
- In-memory Map per server instance
- 5 failed login attempts per 15-minute window per IP
- Returns HTTP 429 with `Retry-After` header

File Upload
- Nuxt built-in `readMultipartFormData()`
- Max file size: 5 MB

Hosting
- Render Web Service

File Storage
- Local filesystem (V1)
- Future: object storage

## Environment Variables

| Variable | Description |
|---|---|
| `DATABASE_URL` | SQLite file path, e.g. `file:/data/prod.db` (dev: `file:/data/dev.db`) |
| `SESSION_SECRET` | Random 32+ character string for encrypting session cookies |
| `ADMIN_EMAIL` | Admin login email |
| `ADMIN_PASSWORD_HASH` | bcrypt hash of the admin password (generated by seed script) |

---

## Admin Account Seeding

The first admin account is created by running the seed script after the database is initialized:

```
npm run db:seed
```

The seed script reads `ADMIN_EMAIL` and `ADMIN_PASSWORD` from the environment (not `ADMIN_PASSWORD_HASH` — the script hashes it), inserts the admin row, and prints the resulting hash for reference.

On Render, run the seed via the Render shell after the first deploy. On subsequent deploys the seed script is idempotent (skips if the admin already exists).

## Hall of Fame Page `/hall-of-fame`

All-time aggregated records derived from stored data. Sections:

**Top Scorers All-Time** — Players ranked by total `SUM(goals)` across all seasons. Shows: rank, player canonical name, total goals, total appearances.

**Assist Leaders All-Time** — Players ranked by `SUM(assists)`. Shows: rank, player canonical name, total assists, total goals.

**Most MOTM Awards** — Players ranked by `SUM(motm)`. Shows: rank, player canonical name, total motm.

**Most Appearances** — Players ranked by `SUM(appearances)`. Shows: rank, player canonical name, total appearances.

**Team Titles** — Teams ranked by number of seasons where they are `winner_team_id` in `TournamentSeason`. Shows: rank, team canonical name, titles count.

**Most Decorated Teams** — Teams ranked by total seasons where `finish_position <= 2` in `SeasonTeamStats`. Shows: rank, team canonical name, podium count (1st/2nd breakdown).

Each section is limited to top 10 by default.

---

## Records Page `/records`

All-time single-season bests derived from stored data. Sections:

**Player Records (single season):**
- Most goals in a season: player, season, tournament, goals
- Most assists in a season: player, season, tournament, assists
- Most MOTM in a season: player, season, tournament, motm count
- Best average rating in a season (min 5 appearances): player, season, tournament, rating
- Most appearances in a season: player, season, tournament, appearances

**Team Records (single season):**
- Most goals scored in a season: team, season, tournament, goals_for
- Fewest goals conceded in a season (min 5 games played): team, season, tournament, goals_against
- Most wins in a season: team, season, tournament, wins
- Highest points in a season: team, season, tournament, points

Each record shows one entry (the all-time best). In the event of a tie, show all tied entries.

Workflow:

6. System: update any `TournamentSeason.winner_team_id` or `runner_up_team_id` that references source team to reference target team

- Admin can proceed only if at least one row is valid

**Step 3 — Confirm**
- Admin clicks "Confirm Import"
- System saves all valid rows, skips error rows
- Import log entry created with final counts and status

# 10. Admin Authentication

## Login Page `/admin/login`

Email + password form. On success, sets session cookie and redirects to `/admin`.

## Auth Middleware

Nuxt server middleware at `server/middleware/auth.ts` intercepts all `/api/admin/*` routes. Returns HTTP 401 if no valid session exists.

Nuxt route middleware at `middleware/admin.ts` intercepts all `/admin/*` page routes (except `/admin/login`). Redirects to `/admin/login` if no session.

## Session Configuration

Managed via `useSession()` from `h3`.

- `httpOnly: true`
- `secure: true` (production)
- `sameSite: strict`
- `maxAge: 86400` (24 hours)

## Rate Limiting

Applied only to `POST /api/auth/login`.

- Window: 15 minutes
- Limit: 5 failed attempts per IP
- On limit exceeded: HTTP 429, body `{ message: "Too many login attempts. Try again later." }`, header `Retry-After: 900`
- Successful login resets the counter for that IP
- Counter stored in server-side in-memory Map (resets on server restart — acceptable for V1)

## Password Requirements

Minimum 10 characters. Enforced at seed time and noted in admin documentation.

# 12. CSV Import System

## CSV Column Specification

### team_stats CSV

Required columns (exact header names, case-insensitive):

```
team_name, played, wins, draws, losses, goals_for, goals_against, points, finish_position
```

Example row:
```
FC Example, 14, 10, 2, 2, 38, 14, 32, 1
```

### player_stats CSV

Required columns (exact header names, case-insensitive):

```
player_name, team_name, appearances, goals, assists, clean_sheets, motm, average_rating
```

`clean_sheets`, `motm`, and `average_rating` are optional per row (can be empty, will be stored as null).

Example row:
```
xXSniper99Xx, FC Example, 12, 15, 4, , 3, 8.2
```

---

## Import Matching Logic

### team_stats import

1. Look up `team_name` in `TeamAlias.display_name` (exact match, case-insensitive).
2. If found: use the associated `Team`.
3. If not found: create a new `Team` with `canonical_name = team_name`, auto-generate slug, and insert a `TeamAlias` with `display_name = team_name`.
4. Upsert `SeasonTeamStats` for the resolved `(season_id, team_id)`.

### player_stats import

1. Look up `player_name` in `PlayerAlias.display_name` (exact match, case-insensitive).
2. If found: use the associated `Player`.
3. If not found: create a new `Player` with `canonical_name = player_name`, auto-generate slug, and insert a `PlayerAlias` with `display_name = player_name`.
4. Resolve team by looking up `team_name` in `TeamAlias` (same logic as above — create if missing).
5. Upsert `SeasonPlayerStats` for the resolved `(season_id, player_id)`.

### Upsert behaviour

If a `(season_id, team_id)` or `(season_id, player_id)` row already exists (e.g., re-importing after a correction), the existing row is overwritten with the new values. This is intentional — admins fix mistakes by re-importing a corrected CSV.

### Row validation

A row fails validation (skipped, counted in `rows_failed`) if:

- Any required numeric field (`played`, `wins`, `draws`, `losses`, `goals_for`, `goals_against`, `points`, `finish_position` for teams; `appearances`, `goals`, `assists` for players) is missing or non-numeric.
- `team_name` or `player_name` is blank.

# 13. Player Merge Tool

## Workflow

1. Admin searches and selects **source player** (the duplicate to remove).
2. Admin searches and selects **target player** (the canonical record to keep).
3. System displays a preview:
   - List of `SeasonPlayerStats` rows that will be re-assigned to target
   - List of aliases that will be moved to target
   - Any aliases that will be skipped (already exist on target)
4. Admin confirms.
5. System (in a single database transaction):
   - Updates all `SeasonPlayerStats.player_id` from source to target
   - Inserts all `PlayerAlias` rows from source to target, skipping any `display_name` that already exists on target
   - Deletes source `PlayerAlias` rows
   - Deletes source `Player` record
6. Success screen with summary.

---

# 14. Team Merge Tool

## Workflow

1. Admin searches and selects **source team** (the duplicate to remove).
2. Admin searches and selects **target team** (the canonical record to keep).
3. System displays a preview:
   - List of `SeasonTeamStats` rows that will be re-assigned
   - Any `TournamentSeason` winner/runner-up references that will be updated
   - List of aliases to be moved, with duplicates flagged
4. Admin confirms.
5. System (in a single database transaction):
   - Updates all `SeasonTeamStats.team_id` from source to target
   - Updates all `SeasonPlayerStats.team_id` from source to target
   - Updates `TournamentSeason.winner_team_id` where it equals source → target
   - Updates `TournamentSeason.runner_up_team_id` where it equals source → target
   - Inserts all `TeamAlias` rows from source to target, skipping duplicates
   - Deletes source `TeamAlias` rows
   - Deletes source `Team` record
6. Success screen with summary.

# 15. File Upload Rules

Accepted MIME types:

- `image/jpeg`
- `image/png`
- `image/webp`

Accepted extensions: `.jpg`, `.jpeg`, `.png`, `.webp`

Validation steps (server-side, in order):

1. Check Content-Length header — reject if over 5 MB before reading body
2. Read file buffer
3. Validate MIME type against accepted list
4. Validate file extension against accepted list
5. Rename file to a UUID-based name (e.g. `a3f9c2d1.webp`) to prevent path traversal
6. Save to uploads directory
7. Store relative URL path in database field

Development upload path: `/public/uploads/`
Production upload path: `/data/uploads/`

The production path must be served as static files. In Nuxt config, define a custom `nitro.publicAssets` entry pointing to `/data/uploads` at URL prefix `/uploads`.

## Leaderboard Queries (corrected)

**Top scorers all-time:**
```sql
SELECT player_id, SUM(goals) AS total_goals, SUM(appearances) AS total_appearances
FROM SeasonPlayerStats
GROUP BY player_id
ORDER BY total_goals DESC
LIMIT 10
```

**Assist leaders all-time:**
```sql
SELECT player_id, SUM(assists) AS total_assists
FROM SeasonPlayerStats
GROUP BY player_id
ORDER BY total_assists DESC
LIMIT 10
```

**Team titles (uses winner_team_id — corrected from v1):**
```sql
SELECT winner_team_id AS team_id, COUNT(*) AS titles
FROM TournamentSeason
WHERE winner_team_id IS NOT NULL
GROUP BY winner_team_id
ORDER BY titles DESC
```

**Most goals in a single season (record):**
```sql
SELECT player_id, season_id, goals
FROM SeasonPlayerStats
ORDER BY goals DESC
LIMIT 1
```

## Architecture Rules

- API route files must remain thin — validate input, call a service, return result
- All database queries must live in `server/services/`
- Drizzle schema is the single source of truth — all types derive from it
- CSV parsing logic isolated in `server/utils/csv.ts`
- Slug generation centralized in `server/utils/slug.ts`
- File upload handling lives only in `upload.service.ts`
- Session helpers centralized in `server/utils/session.ts`
- No raw SQL outside of `server/services/` (use Drizzle query builder)

# 20. Security Checklist

- [ ] All admin API routes check session via server middleware
- [ ] All admin page routes check session via client middleware
- [ ] Login rate limited to 5 attempts per 15 minutes per IP
- [ ] Session cookie: httpOnly, secure, sameSite=strict, maxAge=24h
- [ ] File uploads: MIME + extension validated, UUID renamed, size capped at 5 MB
- [ ] Uploaded file paths never constructed from user input directly
- [ ] Player/team merge operations wrapped in a database transaction
- [ ] Import confirm step is separate from upload step (no auto-save on upload)
- [ ] DELETE endpoints check for dependent records before deleting
